# Publication preparation

## Current policy blocker

The [OpenAI plugin guidelines](https://developers.openai.com/plugins/plugin-guidelines#third-party-content-and-integrations), fetched 2026-10-16, require authorized access to third-party content and prohibit approval of plugins primarily functioning as unofficial third-party connectors. ACMP Connect currently fits that description. MIT licensing and a user authorizing their account do not establish ACMP's authorization for a public integration.

Do not claim publication, approval, official affiliation or current directory eligibility. A personally configured MCP server and directory distribution are separate paths. Before submission, obtain appropriate ACMP authorization, verify its terms and clarify eligibility with OpenAI. Do not rebrand the same connector to evade review.

## Reviewer scenario

1. Sign into OAuth with a dedicated reviewer identity.
2. Open the connection page and link an authorized ACMP test account. Share reviewer credentials only through the review system's secure mechanism.
3. Read problem 1 and resolve topic A from a topic URL.
4. Generate C++ code and explicitly approve one upload.
5. Check the actual final verdict. Repeat the same key and verify no second upload.
6. Inspect an authorized failing submission, disconnect and delete local data.

A real HTTPS deployment, configured OAuth issuer and clients, verified resource binding and refresh, a real ChatGPT connection, ACMP authorization and terms review, directory eligibility clarification, public operator policy/support URLs and reviewer access remain external work. Desktop/mobile behavior needs product-specific verification. Local tests do not establish any of these.
